# Чек-лист проверки olcRTC на устройстве (0.3.0)

Проверяем именно тот сценарий, из-за которого фикс и делался. Пока он не пройден на живом
устройстве, баг считается не подтверждённым как исправленный — тесты и байткод это не заменяют.

## Что поставить

`app-release.apk` из релиза v0.3.0 (подпись `CN=RedSharm`, `versionCode 30000`).
Встаёт **поверх** 0.1.9 без удаления. Проверить версию: Настройки → О приложении → «Версия»
(там же подпись-подсказка «Нажмите, чтобы отправить лог»).

## Шаги

1. **Базовый случай.** Включить VPN на Amnezia EU, дать подключиться, выключить VPN,
   выключить раздельное туннелирование, выбрать **Telemost**. Ожидание: приложение не
   зависает и не вылетает, идёт «Подключение…», затем либо CONNECTED, либо внятная причина
   в статусе («комната не ответила за 25 с (сеть)» и т.п.) — но не молчаливый возврат.
2. **Повтор после неудачи.** Если не подключилось — тапнуть Telemost ещё раз. Ожидание:
   вторая попытка стартует сразу, а не «висит» 10+ секунд (это был утёкший рантайм,
   державший порт 8788).
3. **Переключение на ходу.** На активном Amnezia EU выбрать Telemost. Ожидание: туннель
   перезапускается на Telemost (раньше тап при CONNECTED не делал вообще ничего).
4. **Отмена во время подключения.** Выбрать Telemost и сразу выключить VPN кнопкой.
   Ожидание: состояние возвращается в «Отключено», приложение не залипает в «Подключение…».
5. **Раздельный туннель.** Повторить шаг 1, но с включённым раздельным туннелированием
   (по приложениям и по доменам) — порт 8788 и TUN не должны конфликтовать.

## Если что-то не так

Настройки → О приложении → тапнуть по строке **«Версия»** → «Поделиться» → отправить
файл `redshift_diag.txt`. Внутри: `redshift_debug.log` (с метками `[VPN]` по попыткам),
`singbox/err.txt`, `config.json`, последние падения и текущее состояние.

Что искать в логе:

| Запись | Значение |
|---|---|
| `olcRTC runtime ready (...)` | комната поднялась, рантайм опубликован |
| `olcRTC start superseded, runtime discarded` | попытку отменили, рантайм погашен |
| `olcRTC abandoning unpublished runtime` | сработала защита от утечки (следующая попытка не упрётся в 8788) |
| `connect failed: комната не ответила за 25 с` | комната/сеть, а не приложение |
| `olcRTC runtime stop error` / `executor refused stop` | проблемы гашения — присылать сразу |

## Известный серверный контекст

- Живой URI: `olcrtc://telemost?vp8channel<vp8-fps=30&vp8-batch=64>@85010346785956#dec77c7e…$NL / Telemost`
- На NL `olcrtc.service` активен, cron `health_check.sh` пишет `UNKNOWN STATE` каждые 5 минут —
  это нормально: он ищет в журнале строку `Link connected` за последние 5 минут, которой при
  отсутствии клиентов нет.
- В журнале сервера полезно смотреть `session opened: id=… device=…` / `peer connected: device=…`:
  с 0.3.0 device id стабилен между попытками (раньше это было новое устройство каждый раз).
