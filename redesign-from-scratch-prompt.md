## Роль

Ты — старший Android UI/UX-дизайнер и разработчик Jetpack Compose. Твоя задача — **спроектировать дизайн экрана Home заново, с нуля**, опираясь ТОЛЬКО на эталонный скриншот-референс, и выдать ПОЛНУЮ, готовую к реализации спецификацию. Никаких «примерно»: каждый размер в dp, каждый цвет в HEX, каждый слой описан явно. По этой спецификации другой разработчик должен переписать экран так, чтобы он был визуально максимально близок к референсу.

## Что я хочу на выходе (полный пакет для реализации)

### 1. Дизайн-манифест (одним абзацем)
Главная идея композиции: что является визуальным якорем (ключевой акцент) экрана, какая цветовая температура, настроение, иерархия. Плюс список ВСЕХ элементов, которые есть на референсе (сверху вниз, слева направо), с пометкой назначения каждого.

### 2. Токены дизайна
- Палитра: фон/градиенты, поверхности, бордеры, тексты (primary/secondary/muted), статусные (connected/connecting/error/warning ), акценты. Всё в HEX.
- Типографика: для каждого текстового элемента — размер (sp), начертание, межбуквенный интервал, регистр.
- Размеры: радиусы, отступы (одна сетка), высоты компонентов, тач-таргеты.

### 3. Компоновка экрана (blueprint)
- Поэтапно, сверху вниз: каждый блок указывается с высотой в dp, отступами, горизонтальным позиционированием (по центру/на всю ширину/с полями), боредером/фоном/эффектами.
- Где какой элемент живёт: топбар → hero (таймер/статус/кнопка) → карточки → ряды → навбар.
- Чётко скажи, какие элементы референса являются карточками, какие — голой типографикой, какие — декоративными эффектами (свечение, градиент, блюр, кольца, тени), и КАК их повторить в Compose (drawBehind, Box, Brush и т.п.).

### 4. Спека каждого компонента
Для каждого элемента: название компонента, размеры (dp), цвета, внутренние отступы, текст/иконка/данные, поведение (клик/анимация), состояния. Данные реальные (из списка ниже), ничего не выдумывать.

### 5. Состояния экрана
Опиши, что меняется на экране: DISCONNECTED → CONNECTING → CONNECTED → ERROR (если применимо) и при первом запуске без сервера. Для каждого состояния: что видно, что скрыто, цвета, тексты.

### 6. Анимации
Только те, что видны на референсе или очевидно подразумеваются (пульс кнопки, свечение, плавные переходы статусов, появление карточек). Параметры: длительность, easing, повтор.

### 7. Адаптивность и доступность
- Как экран ведёт себя на узких (360dp) и широких (430dp+) экранах; поведение кнопки 148/164/176dp.
- Тач-таргеты ≥48dp, контраст, некритичность цвета, крупный шрифт, reduce-motion.
- contentDescription для иконок.

### 8. Правила «нельзя» и ограничения (обязательны)
- НЕЛЬЗЯ: emoji-флаги, фейковые данные (серверы/скорости/пинги/таймер), изменение бизнес-логики (подписка, импорт, AWG), изменение модели данных.
- Реальные источники данных, которые можно показывать: выбранный сервер (имя/endpoint/порт/пинг), длительность сессии, download/upload скорости, список недавних серверов, тариф/подписка.
- Если на референсе что-то не видно (текст мелкий/размыт) — НЕ ДОМЫСЛИВАЙ, а пометь «[не видно — нужно допущение]» и предложи обоснованное допущение.

### 9. Порядок внедрения
Расставь шаги реализации по порядку (что спроектировать/закомпоновать первым, вторым и т.д.), чтобы разработчик переписывал экран итерациями и каждый шаг был проверяем.

### 10. Checklist проверки
Чек-лист «как я сам пойму, что переделка попала в референс» — сравнение пиксель-в-пиксель по ключевым точкам.
